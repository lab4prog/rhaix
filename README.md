# rhaix

English version: [README.en.md](README.en.md).

Серверний рендер HTML на HTMX з компонентним підходом.
Ядро — Rust, скриптова мова для бізнес-логіки — [Rhai](https://rhai.rs), DX — як в Astro.

Людина пише тільки файли `.rhx`: розмітка плюс невеликий блок логіки згори.
Ніякого Rust, ніякої збірки фронтенду, ніякого `node_modules`. Деплой —
копіювання одного файлу.

```
pages/todo.rhx
---
let todos = db.find("todos", #{ done: false }, #{ sort: "id desc" });
page.title = "ToDo";
---
<h1>ToDo</h1>
<ul id="list">
  <TodoItem @for={t in todos} todo={t} />
  <li @if={todos.is_empty()} class="empty">Порожньо</li>
</ul>
```

## Встановлення

Готові архіви з `rhaix` і мовним сервером `rhaix-lsp` під Linux, macOS і
Windows додаються до кожного [релізу на GitHub](https://github.com/lab4prog/rhaix/releases).
Або з вихідного коду (потрібен Rust 1.88+):

```bash
cargo install --git https://github.com/lab4prog/rhaix rhaix-cli
```

```bash
rhaix new myapp && rhaix dev myapp
```

Для розробки й запуску застосунку потрібен лише бінарник `rhaix`. Для
`rhaix build` (один самодостатній файл на застосунок) — ще й Rust-тулчейн.
Покроково — у [GUIDE.md](GUIDE.md).

## Стан

## Що всередині

**Мова й компоненти**

- `{{ вираз }}` з екрануванням за контекстом: текст, атрибут, URL, `<script>`;
  `onclick={…}` з даних — помилка компіляції;
- директиви `@if` / `@else-if` / `@else` / `@for` / `@class` / `@style` / `@attr` /
  `@html` / `@text` / `@oob` — остання оновлює блок поза основною ціллю тією
  самою відповіддю;
- компоненти `<TodoItem todo={t} />`, `<Ui.Card>` з props, `{...spread}`,
  звичайними й іменованими слотами та ізольованою областю видимості;
- `<style>` і `<script>` поруч із розміткою компонента; ядро піднімає їх у
  документ один раз, `<style scoped>` звужує селектори до свого файлу;
- спільні функції в `scripts/*.rhai` видно з будь-якого файлу без `import`.

**Маршрути й HTTP**

- маршрути зі структури тек: `pages/` — сторінки, `partials/` — фрагменти,
  `[id].rhx` — динамічні сегменти;
- правило фрагмента: htmx-запит отримує розмітку сторінки без layout, boosted-перехід
  — повну сторінку;
- `api/` віддає JSON: повернена мапа серіалізується сама, помилки теж JSON,
  сесії там немає навмисно; CORS одним рядком конфігу, `rhaix openapi` виводить
  опис OpenAPI 3.1 із самих файлів;
- `middleware.rhx` — спільна охорона для всіх сторінок, готовий рецепт ролей і
  прав у [examples/cookbook](examples/cookbook);
- живі оновлення: `live.send("orders")` на сервері — і кожна відкрита сторінка з
  `hx-trigger="live:orders from:body"` перезапитує свої дані.

**Дані**

- два драйвери, `sqlite` і `postgres`: той самий `.rhx` працює на обох, зміна
  драйвера — це зміна `rhaix.toml`;
- переносимий CRUD (`db.find/get/insert/update/delete`) зі словником операторів
  і власний SQL із `?`-плейсхолдерами; `db.tx` — усе або нічого;
- міграції з `migrations/*.sql` застосовуються на старті;
- `db.grid` — таблиця для адмінки одним викликом: сортування, фільтри й сторінки
  живуть в адресі; `db.attach` прибирає запит на кожен рядок таблиці;
- обмежений пул з'єднань і кеш підготовлених запитів на обох драйверах.

**Безпека**

- сесія — підписаний cookie, що переживає перезапуск і продовжується, поки
  нею користуються;
- CSRF не треба вмикати: форма отримує приховане поле, кнопка з `hx-delete` —
  заголовок, а запит без токена не доходить навіть до `middleware.rhx`;
- паролі на Argon2id (`hash_password`/`verify_password`), обмеження спроб
  `state.allow(key, max, seconds)`;
- скрипт обмежений за часом і кількістю операцій: нескінченний цикл дає помилку,
  а не зависання.

**Батарейки**

- `validate()` — перевірка форми одним викликом, `paginate()` — уся арифметика
  сторінок;
- завантаження файлів зі звіркою шляху, пошта (`mail.send`; без SMTP — у лог);
- `http.get(url).json` прямо у frontmatter, без `await`; чужий API, що лежить,
  дає `ok: false`, а не 500;
- вивантаження: `res.download("звіт.csv", csv(rows, #{ columns: [...] }))` —
  RFC 4180, знешкоджені формули, BOM для Excel, кирилиця в імені файлу;
- дати, `slug()` з транслітерацією, `money()`, переклади `t("ключ")`;
- власні функції на Rust у `native/lib.rs` — коли Rhai не вистачає.

**Клієнт**

- htmx вшитий у бінарник: застосунок не залежить від CDN;
- ядро `rhaix.js` свопить і відповіді `422`/`403`/`404`, тож помилки валідації
  видно на екрані;
- тости `hx.toast(...)` переживають редірект, `<dialog>` сам стає модальним
  вікном; інтерфейс можна перевизначити однією функцією або забрати в проєкт
  цілком (`rhaix eject ui`).

**Інструменти й деплой**

- `rhaix dev` — живе перезавантаження за ~70 мс; кеш знає залежності, тож
  правка компонента оновлює сторінки, що його вбудували;
- помилки в координатах `.rhx` (`pages/todo.rhx:7:26`) з кареткою й підказкою;
  невідомий компонент чи цикл залежностей — помилка компіляції;
- `rhaix check` перевіряє проєкт без запуску й попереджає про типові пастки;
- `rhaix build` вшиває всі файли в один бінарник, який читає з диска лише базу;
  `rhaix serve` — той самий застосунок із диска в режимі продакшну;
- розширення VS Code з мовним сервером: діагностика, `F12` до компонента,
  доповнення ([editors/vscode](editors/vscode)).

## Чого немає

- **Острівців і клієнтських компонентів** — свідомо: інтерактив — це атрибути
  htmx, `public/*.js` і скрипти компонентів.
- **Драйверів MongoDB і SurrealDB** — трейт `DbDriver` до них готовий.
- **Scoped-слотів, morph-свопів за `@key`, `@transition`** — імена зарезервовані.
- **Перейменування й пошуку використань** у редакторі.
- **`markdown()` у збірках CLI**: функція реалізована за feature `markdown`,
  але `rhaix dev`/`serve`/`build` поки її не вмикають.

## Розробка самого rhaix

Демо з клону репозиторію, без встановлення:

```bash
cargo run --release -p rhaix-cli -- dev examples/demo --port 3000
```

Перевірки — ті самі, що в CI:

```bash
cargo test --workspace --locked
```

```bash
cargo clippy --workspace --all-targets --locked
```

```bash
cargo fmt --all --check
```

Бенчмарки ядра з межами, які не можна перевищувати: обчислення виразів (5 мс)
і повний рендер таблиці на 1000 рядків (10 мс):

```bash
cargo run --release -p rhaix-script --bin rhaix-bench
```

```bash
cargo run --release -p rhaix-template --bin rhaix-render-bench
```

| Крейт | Роль |
|---|---|
| `rhaix-db` | трейт драйвера, переносимий CRUD → SQL, драйвери SQLite і PostgreSQL, пул, транзакції, міграції |
| `rhaix-parser` | джерела, спани, `файл:рядок:колонка`, розділення frontmatter |
| `rhaix-script` | рушій Rhai з лімітами, `req`/`res`/`hx`/`state`, сесії й CSRF, `http`, `db.grid`, `csv`, дати й рядки |
| `rhaix-template` | лексер `.rhx`, AST, компіляція виразів, компоненти, рендер, екранування, scoped CSS |
| `rhaix-server` | axum: маршрути, layout, правило фрагмента, `api/`, живі оновлення, статика, `rhaix check` |
| `rhaix-cli` | команди `new`, `dev`, `serve`, `build`, `check`, `openapi`, `eject ui` |
| `rhaix-lsp` | мовний сервер: діагностика, перехід до компонента, доповнення |
