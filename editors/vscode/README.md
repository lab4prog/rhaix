# rhaix для VS Code

Підсвітка синтаксису й мовний сервер для файлів `.rhx`.

## Мовний сервер

Компілятор rhaix уже вміє показувати помилку з координатами
`файл:рядок:колонка`. Мовний сервер нічого нового не перевіряє — він доносить
**ту саму** помилку в редактор, поки її ще не видно в браузері.

| Можливість | Що робить |
|---|---|
| Діагностика | компілює файл із буфера (навіть незбережений) і підкреслює помилку: невідомий компонент, цикл залежностей, синтаксис розмітки й frontmatter |
| Перехід | `F12` на `<TodoItem/>` відкриває `components/TodoItem.rhx` |
| Доповнення | компоненти проєкту після `<`, директиви після `@`, глобальні об'єкти й функції фреймворку у `{{ }}` і frontmatter |

Помилка з **іншого** файлу (зламаний компонент) показується на початку
поточного з назвою файлу-винуватця — інакше вона просто загубилась би.

### Встановити

`rhaix-lsp` лежить в архіві кожного [релізу](https://github.com/lab4prog/rhaix/releases)
поруч із `rhaix` — достатньо покласти його в PATH. Або зібрати:

```bash
cargo install rhaix-lsp
```

Якщо ставити його в PATH не хочеться, шлях задається налаштуванням
`rhaix.server.path`. Без сервера розширення працює далі — лишається підсвітка.

Що підсвічується окремо від звичайного HTML:

| Що | Приклад |
|---|---|
| frontmatter | блок між `---` згори файлу — як код, а не як текст |
| інтерполяція | `{{ вираз }}`, включно з `{{-` / `-}}` |
| коментар rhaix | `{{! його не видно в HTML }}` |
| директиви | `@if` `@else-if` `@else` `@for` `@key` `@class` `@style` `@attr` `@html` `@text` `@oob` |
| компоненти | `<TodoItem/>`, `<Ui.Card>` — інший колір, ніж у HTML-тегів |
| службові теги | `<rhaix:head/>`, `<rhaix:scripts/>`, `<rhaix:csrf/>`, `<rhaix:raw>` |
| вирази в атрибутах | `href={link}`, `{...attrs}` |
| глобальні об'єкти | `req` `res` `hx` `db` `session` `csrf` `http` `mail` `state` `page` `log` `props` `slots` `iter` |
| функції фреймворку | `t()` `validate()` `paginate()` `url()` `date()` `money()` … |

## Встановити локально

```bash
# у теці editors/vscode
code --install-extension .          # або: скопіювати теку в ~/.vscode/extensions/
```

Для розробки достатньо відкрити цю теку у VS Code і натиснути F5 — відкриється
вікно з увімкненим розширенням.

## Перевірка граматики

Граматику перевіряє той самий токенайзер, що й VS Code:

```bash
npm install vscode-textmate vscode-oniguruma
node check-grammar.cjs
```

Скрипт токенізує зразок `.rhx` і звіряє, що frontmatter, `{{ }}`, директиви,
компоненти й службові теги отримали очікувані scope. Це не «на око»: зламана
граматика валить перевірку.

## Чого поки немає

Перейменування, пошук використань і підказки типів. Наведення (`hover`) теж
поки без опису — доки читаються в `SYNTAX.md`.

## Як це перевіряється

Граматика — `check-grammar.cjs` (див. вище). Мовний сервер — наскрізними
тестами в самому крейті: справжній процес, справжній протокол по stdio,
перевірка діагностики, переходу й доповнення:

```bash
cargo test -p rhaix-lsp
```

Окремо перевіряється, що позиції рахуються в **UTF-16**, а не в байтах:
на рядку з кирилицею підкреслення інакше поїхало б управо.
